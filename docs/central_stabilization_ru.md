В общей ветке дополнительно:

- потоковое SSH не ждёт бесконечно запрос без новой строки, завершившегося родителя с открытым каналом вывода или процесс, закрывший вывод, но продолжающий работать;
- прерывание завершает локальный SSH-процесс; удалённая операция могла продолжиться, поэтому повтор выполняется после чтения фактического состояния;
- stderr отделён от stdout при получении версии, реализации и конфигурации; частичный stdout ошибочной команды не отражается в исключении;
- профиль записывается через временный файл и атомарную замену; ошибка замены сохраняет предыдущий файл; опасные имена и символические ссылки отклоняются;
- на POSIX временный файл имеет права 0600 с момента создания; на Windows требуется отдельная проверка унаследованных ACL (списков прав доступа), обычный chmod её не заменяет;
- серверный init отказывает при наличии отдельной установки AWG 3.1 до изменения её данных, сети и службы.

## Что действительно подтверждено на v6

- Ubuntu 24.04, Python 3.12.3; старые записи Ubuntu 20.04 относятся к прежнему состоянию.
- Отдельная `lanfabric-awg31.service`: `lfawg0`, `10.89.6.1/24`, UDP 5182.
- Два самостоятельных профиля dima/dina импортированы владельцем в AmneziaVPN. Сервер увидел свежие согласования ключей и двусторонние счётчики; каждому передано больше 10 MiB.
- Обычный перезапуск службы сохранил серверную конфигурацию и оба профиля побайтно.
- Не подтверждены DNS, HTTPS, внешний IPv4, отсутствие IPv6-утечки, обмен между телефонами, аварийный перезапуск и полная перезагрузка сервера.

Работающая служба v6 не переносится командой init. Старые результаты не объявляются новым измерением действующего сервера.

Решения для С2–С4:

1. AWG остаётся протоколом. Реализация Go сохраняется отдельно и выбирается явно; отсутствие нового файла у прежней установки означает прежний путь с модулем ядра. Тихая подмена Go/ядра, AWG/WG или современного/старого профиля запрещена.
2. Поставка привязана к закреплённым исходникам и проверенным контрольным суммам компонентов. Сборка разработчиком/в CI допустима; обычная установка не должна требовать ручной сборки пользователя. Конкретный способ выпуска проверяется до включения автоматической загрузки и исполнения.
3. Главные скрипты остаются монолитными, стандартная библиотека Python сохраняется. Публичные расширения команд, формат сохранённого состояния и порядок обновления описываются вместе с реализацией; новые флаги этим документом не добавляются.
4. Восстановление Go применяет полный сохранённый профиль после каждого старта процесса, а не только после загрузки ОС. Открытие защитной цепочки выполняется после проверки реально применённых параметров, участников, порта, адреса и маршрута.
5. Порядок блокировок проектируется до вызовов systemctl: процесс, удерживающий общую блокировку, не должен ожидать дочернюю службу, которой нужна та же блокировка. Принадлежность процесса/сокета/интерфейса подтверждается до остановки или удаления.
6. Миграция v6 сохраняет server/client keys, HeaderProtectionKey, порт, сеть и профили. Сначала приватный контрольный снимок, проверка пригодности возврата и независимого управления, затем согласованное короткое переключение. Инициировать init поверх временной службы запрещено.
7. Исходные телефонные профили направляют IPv4 и IPv6 в туннель, но сервер не предоставляет IPv6-интернет. Требуется проверить отсутствие IPv6-доступа в обход VPN на каждом клиенте. Поведение Windows с двумя маршрутами /1 отличается; гарантировать блокировку при падении туннеля ему нельзя без отдельного решения.

## Приёмочные проверки С5

Проверяются два независимых клиента одновременно. Для каждого записываются система, версия приложения, используемая сеть и результат:

- согласование ключей и осмысленная передача файла/HTTPS не меньше 10 MiB;
- DNS и внешний IPv4, соответствующий VPS; отдельная попытка IPv6 должна подтвердить согласованную политику;
- полезный обмен между участниками, а не только ping, который может блокироваться клиентским сетевым экраном;
- отдельный участник без разрешённого интернета не выходит через VPS; блокировка исключает его из VPN; чужой участник не получает доступ;
- при restart, аварии процесса и полной перезагрузке сохраняются ключи, профили и права; соединение восстанавливается без ручного start/sync;
- обновление не меняет профили; контролируемый отказ возвращает прежние компоненты и совместимое состояние; повтор после обрыва управления не вращает ключи.

Чужие сетевые правила, бот, SSH-доверие и другие серверы не меняются ради этих проверок. Перезагрузка и миграция требуют отдельного задания с подтверждённым доступом для восстановления. Покупка нового VPS автоматически не требуется и не разрешается.
