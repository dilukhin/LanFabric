# V6: проверка исходного состояния перед миграцией

Это следующий ограниченный этап №28 после репозиторных проверок №31–№33.
Документ разрешает только чтение подтверждённого собственного v6 через уже
действующий административный доступ. Перенос, перезапуск, перезагрузка,
изменение доверия и покупка другого VPS в это задание не входят.

## Почему миграция ещё не готова

По LF-20261004-02 временная служба использует `lfawg0`, `10.89.6.1/24`,
UDP 5182. Штатная основа управляет `wg0`, `10.8.0.1/24`.
Одинаковые AWG/Go-компоненты не делают эти установки взаимозаменяемыми.
Клиентские адреса, ключи, HeaderProtectionKey и порт должны сохраняться.
Значения из прежнего отчёта не заменяют свежую проверку.

Перед переключением нужна отдельная реализация сохранённой адресации и
импорта состояния. Текущий `init` правильно отказывает при отдельной службе;
обходить отказ удалением каталога, службы, ключей или правил запрещено.
`patch` тоже не импортирует временную установку и не меняет схему состояния.

## Задание LF-V6-READONLY-01

Исполнитель: локальный агент в уже установленной собственной рабочей области
LanFabric. Правила — `AGENTS.md`, контекст проекта, протокол отчёта и локальный
рабочий процесс. GitHub-операции остаются у ChatGPT Web; локальный push/merge
не требуется. Перед чтением зафиксировать timestamp, branch, HEAD и чистоту
рабочей области; при неожиданном состоянии остановить соответствующий шаг.

Цель: получить достаточно несекретных доказательств, чтобы подготовить код
миграции и проверяемый возврат. Подключаться только к уже подтверждённому
профилю v6, не угадывать адрес и не искать похожий сервер. Использовать
существующий SSH/sudo без нового доверия. Если идентификация или доступ
не подтверждены, вернуть BLOCKED с конкретно недостающим фактом.

Внешние команды ограничить 20 секундами, весь этап — пятью минутами.
Не повторять ту же неработающую команду без нового основания. Не выводить
ключи, HPK, полные `.conf`, `showconf`, `dump`, окружение и необработанный журнал.
Архивы/копии серверного состояния в этом этапе не создаются.

Проверить и вернуть:

| Область | Доказательство без секретов |
| --- | --- |
| Идентичность | Подтверждённый профиль v6, ОС, архитектура, версии Python и ядра; без публичной выгрузки административных данных |
| Служба | `active/enabled`, результат, PID; совпадение файла/загруженного определения и отсутствие незнакомых дополнений; только выбранные свойства systemd |
| Процесс | Совпадение PID, пути/аргументов Go, группы службы и сокета; неизвестный процесс не останавливать |
| Постоянные файлы | Пути, типы, root-владелец и права `/opt/lanfabric-awg31`, `state`, `bin`, скрипта и службы; контрольные суммы публичного кода/бинарников |
| Совместимость | Фактические суммы Go/tools совпадают с прежним manifest и закреплённой проверенной поставкой; результат сравнения, не секретные значения |
| Приватное состояние | Полный набор полей AWG 3.1, сохранённые пары ключей соответствуют друг другу, два разных участника, корректные IP; только результаты проверок |
| Адресация | Фактические интерфейс, IPv4-сеть/адрес сервера, порт, MTU, внешний интерфейс и проверенный маршрут; предполагаемые значения не подставлять |
| Политики | Принадлежность LF31-IN/FWD/NAT и их подключений, отсутствие незнакомых пересечений; остальные правила читать/сравнивать приватно, не публиковать целиком |
| Занятость новой цели | Наличие `/opt/vpn-admin`, wg0, штатных служб/цепочек, пересечений подсети и портов; ничего не очищать |
| Возврат | Существующий независимый административный канал подтверждён действующим доступом; способ восстановления известен, новый ключ/разрешение не создавать |
| Клиенты | Доступность двух устройств, ОС/версия приложения/сеть и последние подтверждённые результаты; отсутствие клиента обозначить BLOCKED |

Источник структуры временной службы — `deployment/awg31_service.py` в
репозитории: `state/manifest.json`, `server.conf`, отдельные клиентские `.conf`,
`bin/amneziawg-go`, `bin/awg`, `lanfabric-awg31.service`, собственные LF31-цепочки.
Фактическое содержимое могло отличаться от текущего файла: его идентичность
проверяется, не предполагается. Приватные файлы допускается читать внутри
ограниченного проверяющего процесса и сравнивать в памяти; их содержимое
не выводится и не сохраняется в GitHub.

Отчёт — по `docs/task_report_protocol_ru.md`, в локальном каталоге отчётов;
служебный отчёт не коммитить. Для каждой строки дать PASS/FAIL/BLOCKED и
доказательство. Итог: серверные мутации отсутствуют, текущая служба и профили
сохранены. Если чтение подтвердило проблему, описать её и остановиться.

## Что подготовить после отчёта

1. Совместимый формат сохранённой адресации и его проверку до работы службы;
   отдельный импорт исходного состояния в SQLite без генерации ключей.
2. Изолированный сценарий с той же сетью, портом и двумя синтетическими
   профилями: миграция, отказ и возврат, повтор после обрыва, сохранение профилей
   побайтно. Прежние установки и журналы обновления тоже проверяются.
3. Конкретную карту переключения и приватного снимка: точные пути, службы,
   правила, сроки и команды возврата; независимый доступ проверяется до остановки.
   Никаких глобальных очисток и изменений чужих ресурсов.
4. После проверки кода — отдельное согласованное серверное переключение.
   При отказе вернуть прежние компоненты, службу, правила и состояние;
   профили и разрешения сверить, клиентское соединение восстановить.

Отдельная реальная приёмка требует двух клиентов одновременно: DNS, HTTPS/файл
не меньше 10 MiB, внешний IPv4 VPS, согласованная политика IPv6, полезный обмен
между участниками, блокировка и отсутствие интернета у запрещённого участника.
Нужны успешное обновление/возврат, аварийное восстановление и холодная загрузка
с сохранением профилей. Результаты пишутся по каждому устройству/сети.

Для Ubuntu 20.04 остаётся проверка с собственным ядром этой ОС; контейнер
проверяет пользовательскую среду, системный Python и systemd на ядре CI-машины.
Новый VPS автоматически не требуется и этим заданием не приобретается.
V1/V4/V5, V3, dilyavm и бот не используются; V2/vslava остаются только ранее
разрешёнными резервными административными каналами, без испытательного VPN-трафика.

№28 и решение о выпуске остаются открытыми до подтверждения этих условий.
