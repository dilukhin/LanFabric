# AWG 3.1 и сохраняемый порт: кандидат для v6

Статус: экспериментальная доработка 0.0.18 поверх PR №24. Не подтверждает работающий VPN на v6. Версия модулей не изменена.

## Изменения

Прежний профиль из девяти полей продолжает читаться и остаётся форматом новой установки по умолчанию. Полный современный профиль сохраняется без потери дополнительных полей при чтении, записи, восстановлении и экспорте клиенту. Неизвестные поля, повторные строки, неполный современный профиль и повреждённые значения вызывают ошибку. Сообщения не включают значения параметров или строки конфигурации.

Новый профиль выбирается явно: `init --awg-profile awg31`. В нём S1–S4 равны 12, H1–H4 равны 1–4; создаётся свежий ненулевой 32-байтовый HeaderProtectionKey в base64. Используются интервалы и переключатели проверенного профиля AmneziaVPN 5.0.3.0. Это совместимый кандидат без I1–I5, а не полная копия всех параметров официального установщика. I1–I5 пока явно отклоняются: их синтаксис CPS требует отдельной реализации и проверки. Устойчивость к фильтрации не следует из одного набора параметров.

`init --listen-port PORT` задаёт порт 1..65535. Он сохраняется в защищённом `/opt/vpn-admin/listen_port` и используется сервером, клиентским Endpoint и диагностикой. Отсутствующий файл в прежнем состоянии означает 51820 без создания файла. Повреждённый существующий файл не подменяется значением по умолчанию. При `init` без выбора порта читается прежнее значение. `start`, `status`, `health`, `config` не создают порт или профиль.

При явном выборе профиля, отличающегося от сохранённого, `init` отказывает перед удалением ключей, БД и интерфейса. Без явного выбора сохранённый профиль используется. Эти проверки не делают `init` недеструктивным: обычная команда по-прежнему переинициализирует серверные ключи; перед входом в неё основной диспетчер отменяет выполняющуюся загрузочную службу. Для действующей установки нужен отдельный план обновления.

Перед открытием защитной цепочки современный профиль сверяется с реально прочитанными полями интерфейса. Отсутствующее поле, несовпадение, отказ программы или таймаут не позволяют открыть доступ. Ключ сравнивается внутри процесса и никогда не включается в диагностику. Ошибка `setconf` не печатает stderr, который может содержать отвергнутую строку с ключом. Порт проверяется точным фильтром `ss`, без поиска совпадающего хвоста.

## Реализация и границы проверки

LanFabric по-прежнему использует **модуль ядра AmneziaWG**: `modprobe`, `ip link ... type amneziawg`. Поддержка `amneziawg-go` этой доработкой не добавлена. Установка новой утилиты поверх старого модуля не считается обновлением протокола. Источник пакетов в существующем `init` остаётся прежним; для реальной установки нужно отдельно подтвердить фактическую сборку модуля и tools.

Схема профиля проверяется до очистки, но фактическая поддержка ядром проверится при восстановлении интерфейса. Поэтому **первый реальный запуск допустим только после проверки чистоты v6 и испытания выбранных компонентов на отдельном временном интерфейсе по следующему установочному заданию**. Текущий LF-20261004-01 таких изменений не разрешает; он собирает исходные сведения.

Обратное чтение проверено по исходникам tools `ee0f0a9aa34ff0a0da4b3433b9512781cfe02843` / `v3.1.20260812`. Имя поля числа попыток в этой сборке — `max-handshake-attemps` с опечаткой upstream. Другая сборка должна быть проверена; неизвестное поле вызывает отказ. Строка версии Go сама по себе не доказывает поддержку современного профиля.

Локальные тесты используют подмены системных команд и временные файлы. Они проверяют сохранение параметров, секреты в ошибках, отказ при несовместимости, сохранённый порт, экспорт и закрытую защитную цепочку. Они не подтверждают работу модуля ядра, подключение из РФ, передачу данных и восстановление после перезагрузки.

## Перед поставкой на v6

1. Получить отчёт LF-20261004-01: существующие службы, доступность из нужных сетей РФ, ОС/ядро, компоненты, клиенты и сетевые экраны.
2. Проверить выбранные tools/модуль с полным профилем на временном интерфейсе; сравнить применённые поля без вывода ключей. Не считать номер пакета доказательством совместимости.
3. Если совместимый модуль недоступен, отдельно подготовить пользовательский процесс Go и его жизненный цикл; не переключать backend молча.
4. Выбрать свободный порт по фактическому отчёту; отдельно согласовать INPUT и внешний сетевой экран. LanFabric управляет FORWARD/NAT, но не открывает входящий UDP автоматически.
5. Зафиксировать точный commit и SHA256 обоих модулей. `vcli init` и `patch` пропускают копирование при одинаковой версии 0.0.18: новая функциональность не появится на уже установленном 0.0.18 автоматически. До поставки определить выпуск или явную проверяемую доставку; не обходить проверку версии скрытым копированием.
6. Установить на подтверждённо подходящий v6 и проверить dima/dina: handshake, полезные данные в обе стороны, интернет/DNS, связь между клиентами, передачу крупного файла, поведение при отключении и перезапуске, затем перезагрузку сервера при сохранённом административном доступе.
7. Проверить полный IPv4-туннель и поведение IPv6 на клиентах; один успешный handshake не закрывает проверку сервиса. Определить, где клиент блокирует IPv6 вне туннеля, поскольку текущая серверная схема IPv4.

v6 — 45.144.232.170. v1/v4/v5 исключены. v2/vslava принадлежат другим людям и используются только как существующие резервные административные каналы; никакой установки, VPN-трафика или испытаний на них. v3 — собственный административный резерв, его существующие службы сохраняются.
