# AWG Go: поставка и штатная установка

Задача №28, этап С3. Исходная основа управления включена через №30.

## Решение и границы работы

Основные скрипты остаются монолитными, Python 3.10+, стандартная библиотека.
Версия 0.0.18 и схема SQLite не меняются. Работа выполняется в репозитории
и на одноразовых машинах GitHub Actions; реальные VPS не изменяются.

Сборка закреплённых Go/tools выполняется при разработке. Go собирается без CGO,
управляющая утилита — статически; оба файла не требуют динамического загрузчика.
Две последовательные сборки должны дать одинаковые SHA-256. Результаты
публикуются как компоненты `awg-go-3.1-r1`, отдельно от номера выпуска LanFabric.
Обычная установка получает два готовых файла по HTTPS и сверяет контрольные
суммы, встроенные в проверенный серверный скрипт. Ни Go, ни C-компилятор на VPS
не устанавливаются. Неудачная загрузка или несовпадение суммы приводят к отказу.

Публичное расширение: `init --implementation go` выбирает AWG Go явно.
Без флага сохраняется прежний путь; `--no-amnezia` несовместим с Go.
Для Go по умолчанию используется профиль AWG 3.1. Выбор сохраняется отдельным
файлом реализации. Новый путь разрешён только на чистой цели; существующие
ключи, БД, интерфейсы, цепочки и отдельная служба v6 не очищаются ради установки.

Установка проверяет происхождение компонентов, ОС/архитектуру, TUN, место,
порт, подсеть и границу доверия до создания ключей. После подготовки состояния
служба восстанавливает полный профиль и открывает защиту только после проверки.
Остановка systemd не выполняется под общей блокировкой состояния.

`remove REMOVE` для Go останавливает собственную службу и сохраняет ключи,
профиль и БД. `purge PURGE` отдельно проверяет принадлежность удаляемых файлов;
чужие каталоги, пакеты, правила, SSH-ключи и sudoers не удаляются этим путём.
Обновление должно сохранять профили и иметь приватный контрольный снимок.

## Проверки и условия завершения

Локально проверяются конфликты и отказы до мутаций, загрузка повреждённого
компонента, сохранение прежних команд и профилей, порядок блокировок.
На одноразовой машине испытываются реальные штатные команды и аварийное
восстановление. Готовые файлы отдельно запускаются в Ubuntu 22.04/24.04.

Ubuntu 20.04 требует отдельного обеспечения Python 3.10+ без обновления ОС;
статические Go/tools сами эту задачу не решают. Миграция v6, холодная загрузка,
два реальных клиента, DNS/HTTPS/IPv4/IPv6 принимаются отдельным серверным этапом.
Эта запись описывает решение и критерии; фактические результаты добавляются
после проверки конкретного коммита.
