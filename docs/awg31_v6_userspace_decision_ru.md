# v6: отдельная служба AWG 3.1 до интеграции в LanFabric

Дата: 4 октября 2026 года. Решение Web для LF-20261004-02.

## Причина и выбранный путь

Отчёт LF-20261004-01 подтверждает v6 45.144.232.170: Ubuntu 20.04.6, x86_64, ядро 5.4.0-88, 981 MiB RAM, отсутствие AWG/WG и LanFabric. Текущий LanFabric требует Python 3.10+ и модуль ядра. Его локально проверенная поддержка современных параметров из PR №25 не доказывает собираемость модуля на v6 и не решает установочную задачу на Ubuntu 20.04.

Приоритет пользователя — получить VPN с интернетом для dima и dina сейчас. Поэтому для первой поставки выбирается **отдельная служба AWG 3.1 с пользовательским процессом amneziawg-go**. Это временный способ развёртывания сервиса, а не завершённая поддержка Go в LanFabric. Монолитные vcli-admin.py/vsrv-admin.py, их версия, интерфейс команд, доверие SSH/sudo и SQLite не меняются.

Пользователь разрешил обновление Ubuntu при необходимости. Для выбранной реализации обновление ОС не является условием: Go использует TUN, небольшой tools собирается на текущей ОС, установочный помощник совместим с Python 3.8. Плановое обновление ОС можно выполнять отдельно после первого работающего сервиса и сохранения профилей. Автоматический обход несовместимости переключением на прежний AWG/WG запрещён.

## Поставка

- Go: amneziawg-go commit `b5928efb6ca19f0153958460c3d141f04abc5c2e`, собирается вне VPS для Linux amd64 без CGO.
- Tools: commit `ee0f0a9aa34ff0a0da4b3433b9512781cfe02843`, сборка `make -C src -j1 wg` на v6. Не устанавливать системный wg и не добавлять PPA/DKMS.
- Компилятор: официальный Go 1.27.1 с проверкой опубликованной SHA256; отдельный временный каталог на Windows, без замены установленного Go и PATH.
- Каталог службы: `/opt/lanfabric-awg31`, принадлежит root; код/бинарные файлы не доступны на запись группе/остальным, конфигурации и состояние 0600, каталог 0700.
- Интерфейс: `lfawg0`, отдельная служба `lanfabric-awg31.service`. `wg0`, `/opt/vpn-admin` и `/etc/wireguard` не используются.
- Два независимых профиля: dima и dina. Обоим разрешён IPv4-интернет и обмен между VPN-клиентами. Один профиль нельзя одновременно включать на Windows и телефоне: это один peer с одним ключом.
- Частная IPv4-подсеть /24 выбирается после сверки маршрутов клиентов и сервера. Кандидаты 10.89.6.0/24 и 10.89.7.0/24; существующая 10.77.24.0/24 не используется. Порт — первый подходящий из 5182/5183/5184 с повторной проверкой занятости.
- MTU1280 для первой поставки. IPv6 не предоставляется: отдельная проверка клиента должна доказать отсутствие IPv6-доступа вне VPN при заявленном полном туннеле.

## Восстановление и защита

systemd запускает Go явно в переднем плане, сохраняет процесс как MainPID и перезапускает при завершении с ограничением частоты. На v6 с 981 MiB RAM заданы мягкий предел памяти Go256MiB и предел группы процессов512MiB, чтобы оставить память для ОС и SSH. После **каждого** запуска ExecStartPost ограниченно ждёт управляющий сокет, применяет сохранённый полный серверный профиль с обоими peers, сравнивает прочитанные AWG поля и лишь затем поднимает интерфейс. Успешный статус процесса без выполненного ExecStartPost не считается готовым VPN.

Адрес, MTU и состояние интерфейса задаются отдельно: их нельзя передавать в setconf. Обычный awg show/showconf/dump не выводится в диагностику. stderr настройки может содержать HPK, поэтому помощник выдаёт общую ошибку без исходного текста программы. Повторная установка на существующее состояние отказывает и не вращает ключи.

Помощник допускает только подтверждённо пустые затрагиваемые IPv4-цепочки с политикой ACCEPT и однозначный физический WAN. Создаёт отдельные LF31-IN/FWD/NAT и точные переходы в них. Не очищает глобальные правила и не меняет SSH или внешний сетевой экран провайдера. При отказе установки останавливает только свою службу, удаляет только созданные им переходы/цепочки и восстанавливает прежний IPv4 forwarding. Если откат не завершён, ошибка явно отражается в отчёте; успех не объявляется. Если после остановки Go сохранился интерфейс, его принадлежность считается неизвестной: интерфейс и защита не удаляются автоматически.

## Реальная проверка

Локальные проверки Python и чтение upstream подтверждают только логику помощника и формат запуска. Фактическую сборку и работу Go/tools, импорт клиентом, соединение из РФ, полезный трафик, DNS и восстановление нужно выполнить в LF-20261004-02.

Неизвестный внешний UDP firewall проверяется через настоящее подключение после установки и счётчики полезного трафика. Отсутствие ответа на произвольный UDP пакет не доказывает блокировку: AWG не обязан отвечать неизвестному клиенту. Незнакомые приложения на телефонах не являются причиной остановить серверную сборку; готовые профили сохраняются, проверка каждого недоступного устройства получает отдельный BLOCKED.

v1/v4/v5 полностью исключены. v2/vslava — только существующие резервные административные каналы, без VPN или испытательного трафика. v3 не меняется. Бот и dilyavm не затрагиваются.

## После первого сервиса

Конечная цель, уточнённая пользователем: установка на v6/v7/v8 и обновление выполняются штатными `vcli-admin.py` и `vsrv-admin.py`, без обязательного агента и индивидуального архива. PR №26 и LF-20261004-02 являются только первым проверочным этапом. Требования к интеграции, поставке, миграции и критериям готовности закреплены в [плане штатной установки](vpn_standard_installation_plan_ru.md).

Отдельно решить выпуск и интеграцию userspace в обычный LanFabric: модель сохранённой реализации, доказательство принадлежности интерфейса/процесса, совместимые start/stop/sync/autostart, обновление без смены ключей, управляемая миграция двух профилей. Нельзя запускать LanFabric init поверх этой службы или заявлять, что существующий vcli теперь ей управляет.
