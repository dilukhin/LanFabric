## 4.1. Реализация кандидата 0.0.18

По принятому контракту C1–C8 кандидат 0.0.18 реализуется одним целостным change set в последовательности #17 → #15 → обязательная часть #16 → #12:

- restore/status/health не создают потерянные DB/AWG params и используют строгий снимок состояния;
- AWG apply использует собственный fail-closed firewall guard и общий межпроцессный lock;
- root entrypoint устанавливается через staged validation и атомарную root-замену; состояние получает закрытые права;
- persistent autostart управляется явно через `autostart enable|disable|status`, а systemd вызывает внутренний boot restore;
- `start` не меняет persistent autostart; `stop` временный; remove/purge удаляют unit.

Версия кандидата: **0.0.18**. Это patch-релиз без изменения SQLite schema и без требования `init`. Проверенный deployment baseline остаётся 0.0.17 до отдельной приёмки.

Миграция существующей 0.0.17 задана явно: `patch -> autostart enable -> start -> health`. `patch` не включает unit, а `start` может кратко прервать текущих VPN-клиентов.

Кодовая реализация не означает закрытия #12/#15/#17 или всей #16. До merge/deployment обязательны полный локальный regression PASS и review; после него — отдельные deployment и cold-boot gates.
