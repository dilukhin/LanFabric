# LanFabric

LanFabric помогает объединить компьютеры через интернет в частную сеть. Участники получают внутренние адреса и могут обращаться друг к другу по ним: подключаться к общей папке, удалённому рабочему столу или игровому серверу, если соответствующая программа и доступ к ней настроены на компьютере.

Для связи используется VPN — зашифрованное соединение через ваш сервер. LanFabric подготавливает этот сервер, создаёт профили участников и позволяет отдельно решать, кому разрешён выход в интернет через него. Управление выполняется командами из консоли Windows или Linux.

Проект развивается. Это руководство описывает кандидат **0.0.18**: автоматическое восстановление AmneziaWG, проверяемый выход в интернет и сохранение выбранного порта. Полная серверная приёмка ещё не завершена; её условия указаны в [плане стабилизации](docs/central_stabilization_ru.md). Отдельная работающая служба AWG 3.1 на v6 пока обслуживается своим помощником, а не этими двумя скриптами.

## Как устроена сеть

Предположим, два компьютера находятся в разных квартирах. Каждый подключён к своему интернету, поэтому обычной общей локальной сети между ними нет. Вы арендуете VPS — виртуальный сервер с постоянным публичным адресом — и настраиваете на нём LanFabric. Затем каждый компьютер устанавливает зашифрованное соединение с этим сервером. Сервер передаёт данные между участниками.

Внутри VPN сервер имеет адрес `10.8.0.1`, а участники получают адреса от `10.8.0.2` до `10.8.0.254`. Для обращения к другому компьютеру используется именно его внутренний адрес. Публичный адрес сервера нужен для подключения к самой VPN.

Это сеть уровня L3: она связывает устройства по IP-адресам, но не переносит все способы автоматического поиска соседей, привычные в домашней локальной сети. Общая папка может не появиться сама в разделе «Сеть», а игра — не найти сервер в списке локальных игр. Подключайтесь по адресу VPN; для игры это возможно, если она поддерживает ввод адреса сервера. Общие папки, права доступа и разрешения в брандмауэре на компьютерах настраиваются отдельно.

Управление сетью и участие в ней — разные действия:

| Кто и что делает | Где это происходит |
| --- | --- |
| Администратор запускает `vcli-admin.py`, чтобы подготовить сервер или добавить участника | На своём компьютере с Windows или Linux |
| Модуль `vsrv-admin.py` выполняет полученные команды | На сервере Ubuntu; LanFabric сам копирует его туда |
| Участник импортирует свой профиль в приложение AmneziaWG или WireGuard и включает соединение | На каждом подключаемом устройстве |

Для управления используется SSH — защищённый доступ к консоли сервера, а для передачи файлов — SCP. Администратору нужны данные этого доступа. Обычному участнику достаточно своего VPN-профиля; пароль от сервера ему не нужен. Компьютер администратора тоже может быть участником сети, но для этого ему требуется собственный профиль.

### Куда пойдёт интернет-трафик

При создании профиля выбирается один из двух режимов:

| Режим | Что идёт через VPN | Что происходит с обычным интернетом устройства |
| --- | --- | --- |
| Только частная сеть, по умолчанию | Обращения к адресам `10.8.0.x` | Продолжает работать через обычное подключение |
| С разрешением `--internet` | Обращения к частной сети и весь IPv4-трафик в интернет | Выходит через ваш VPN-сервер |

**«Интернет запрещён» означает запрет выхода через сервер LanFabric.** Это не отключает собственный интернет участника и не является средством родительского контроля.

Здесь речь об IPv4 — адресах вида `10.8.0.2`. Настройка IPv6 этой версией не выполняется. Также Windows-профиль не включает аварийную блокировку трафика вне VPN: не следует считать его гарантией того, что при отключении туннеля интернет будет заблокирован.

## Что понадобится

Для первого запуска подготовьте сервер и компьютер, с которого будете им управлять.

**На сервере:** Ubuntu 22.04 или 24.04, Python 3.10 или новее, работающий SSH-доступ и учётная запись с правом `sudo`. Команда `sudo` позволяет выполнять административные действия. LanFabric нужны эти права, чтобы устанавливать пакеты и настраивать сеть. Сам сервер должен иметь доступ в интернет для загрузки пакетов.

Версия Ubuntu сама по себе не подтверждает наличие нужного Python. Проверка `python3 --version` на сервере должна показать 3.10 или новее. Установка или обновление Python в подготовку сервера входит отдельно; LanFabric это требование автоматически не устраняет. Ubuntu 20.04 с исходным Python 3.8 пока не поддерживается штатными скриптами.

В панели провайдера разрешите входящий **UDP-порт 51820** для адресов участников. Если их адреса меняются, правило должно учитывать это. Сетевой экран провайдера может называться «брандмауэр», «firewall» или «группа безопасности». Доступность SSH, обычно по TCP-порту 22, не означает доступность VPN: это разные соединения.

**На компьютере администратора:** Windows или Linux, Python 3.10 или новее и команды `ssh` и `scp`. Для автоматической установки VPN-приложения на Windows потребуется `winget` — средство установки программ. На Linux VPN-приложение устанавливается отдельно.

Перед установкой учитывайте ограничения кандидата:

- Для AmneziaWG программа проверяет внешний сетевой интерфейс и маршрут участников перед разрешением интернета. Неоднозначная маршрутизация или изменение выхода во время применения завершаются ошибкой с запретом трафика.
- Новая установка AmneziaWG включает службу автоматического восстановления. Для прежней штатной установки после `patch` нужно отдельно выполнить `autostart enable`, затем `start` и `health`. Проверка восстановления после полной перезагрузки остаётся частью приёмки.
- Сеть `10.8.0.0/24` и интерфейс `wg0` заданы в программе. Порт по умолчанию `51820`; другой задаётся при `init --listen-port <порт>` и сохраняется. Разрешите именно этот UDP-порт у провайдера. Нужен сервер без конфликтующей VPN и без пересечения сети с используемыми адресами.
- Для AmneziaWG используется модуль ядра Linux. Если его установка или загрузка невозможна, LanFabric завершится ошибкой; автоматической замены на WireGuard нет.
- Параметр `init --awg-profile awg31` выбирает полный профиль AWG 3.1, но сам по себе не устанавливает реализацию Go. Совместимость tools и модуля ядра должна быть подтверждена. Штатная интеграция Go выполняется в [задаче №28](https://github.com/dilukhin/LanFabric/issues/28); `init` рядом с её отдельной установкой отказывает.
- Стандартный WireGuard сохраняет прежний путь установки и NAT через `eth0`. Восстановление участников после его загрузки ещё относится к [задаче №19](https://github.com/dilukhin/LanFabric/issues/19).

Подробности проверенных сценариев находятся в [состоянии проекта](docs/current_status_ru.md), а порядок доработок — в [плане работ](docs/work_plan_ru.md).

## Подготовка к первому запуску

### Получите файлы и проверьте команды

Откройте [репозиторий LanFabric](https://github.com/dilukhin/LanFabric), выберите ветку `master` и скачайте архив через **Code → Download ZIP**. Распакуйте его и откройте консоль в папке, где рядом лежат `vcli-admin.py` и `vsrv-admin.py`. Не переносите только один из этих файлов: для установки и обновления серверного модуля нужны оба.

Проверьте Python и наличие SSH:

```console
python --version
ssh -V
```

Если в Linux Python запускается командой `python3`, используйте её вместо `python` во всех примерах. На Windows аналогично можно использовать `py -3.12`, если Python установлен с таким средством запуска. Нужна версия не ниже 3.10. Команда `scp` без аргументов должна показать краткую справку об использовании; сообщение «команда не найдена» означает, что её требуется установить.

Проверить сам LanFabric можно без обращения к серверу:

```console
python vcli-admin.py --version
python vcli-admin.py --help
```

Для Python-кода проекта не нужны дополнительные библиотеки из `pip`. Системные программы для работы VPN устанавливаются отдельно, в том числе командой `init` на сервере.

### Разберите одну команду

Далее используются вымышленные данные. Замените их своими во всех командах:

| Значение в примере | Что указать вместо него |
| --- | --- |
| `198.51.100.42` | Публичный адрес вашего VPS |
| `donpedro` | Имя пользователя для SSH-доступа к VPS |
| `id_lanfabric` | Путь к вашему закрытому SSH-ключу, без окончания `.pub` |
| `alice`, `bob` | Имена создаваемых VPN-профилей |

SSH-ключ — файл, которым вы подтверждаете право входа на сервер. Примеры предполагают, что вход с этим ключом уже настроен. Если в пути есть пробелы, заключите путь в двойные кавычки.

Вот команда запроса состояния уже установленного сервера:

```console
python vcli-admin.py --host 198.51.100.42 --user donpedro --auth key --key id_lanfabric status
```

Начало запускает программу. Параметр `--host` задаёт сервер, `--user` — пользователя на нём, `--auth key` — вход по ключу, а `--key` — путь к этому ключу. Последнее слово `status` говорит, что нужно сделать. Параметры подключения ставятся **перед** названием действия, параметры самого действия — после него.

Имя `donpedro` и имя профиля `alice` относятся к разным учётным записям: первая управляет сервером по SSH, вторая подключается к VPN.

Если сервер выдал только пароль, вместо `--auth key --key id_lanfabric` используйте `--auth password`. Например, проверить обычный вход по паролю можно командой `ssh donpedro@198.51.100.42`. Особенности такого доступа в LanFabric описаны [ниже](#доступ-к-серверу-по-паролю).

### Проверьте доступ к серверу

С компьютера администратора выполните:

```console
ssh -i id_lanfabric donpedro@198.51.100.42
```

При первом соединении SSH может попросить подтвердить ключ сервера. Сверьте его отпечаток с данными провайдера или администратора. После входа команды выполняются уже **на VPS**:

```console
python3 --version
sudo -v
ip route
```

`sudo -v` проверит административные права и при необходимости запросит пароль. Если доступа или прав нет, сначала настройте их: `init` не заменяет этот шаг. После проверки введите `exit`, чтобы вернуться в консоль своего компьютера.

## Первый запуск: от сервера до подключения

Все команды LanFabric в этом разделе выполняются **на компьютере администратора**, из папки с двумя Python-файлами. Переходите к следующему шагу после успешного завершения предыдущего; читайте сообщения и рекомендации программы.

### 1. Подготовьте сервер один раз

По умолчанию LanFabric использует **AmneziaWG** — вариант WireGuard с изменёнными характеристиками VPN-трафика. На новом сервере выполните:

```console
python vcli-admin.py --host 198.51.100.42 --user donpedro --auth key --key id_lanfabric init
```

Команда установит нужные серверные пакеты, настроит административные права для LanFabric, создаст ключи и сетевой интерфейс, включит передачу пакетов и запустит VPN.

**`init` — первоначальная настройка, а не обычный запуск.** Повторное выполнение очищает прежнее состояние VPN и заменяет серверные ключи. Старые клиентские профили перестанут соответствовать серверу. Не используйте эту команду для исправления случайной ошибки или после каждой перезагрузки.

Если вы осознанно выбрали стандартный **WireGuard**, выполните **вместо** предыдущей команды:

```console
python vcli-admin.py --host 198.51.100.42 --user donpedro --auth key --key id_lanfabric init --no-amnezia
```

Это два взаимоисключающих варианта одного шага. AmneziaWG требует приложения AmneziaWG у участников; WireGuard — приложения WireGuard. Выбор сохраняется на сервере, и LanFabric не меняет его автоматически при ошибках.

### 2. Убедитесь, что VPN запущена

```console
python vcli-admin.py --host 198.51.100.42 --user donpedro --auth key --key id_lanfabric status
python vcli-admin.py --host 198.51.100.42 --user donpedro --auth key --key id_lanfabric health
```

`status` показывает общее состояние. `RUNNING` означает, что VPN запущена, `STOPPED` — остановлена, `BROKEN` — обнаружена несогласованная настройка, `UNKNOWN` — состояние определить не удалось.

`health` проверяет подробнее: интерфейс, порт, передачу пакетов, сетевые правила и базу участников. Эта проверка видит сервер изнутри. Даже успешный результат не доказывает, что провайдер пропускает подключения извне; окончательная проверка будет после подключения участника.

### 3. Создайте профиль участника

Для компьютера, которому нужна только частная сеть:

```console
python vcli-admin.py --host 198.51.100.42 --user donpedro --auth key --key id_lanfabric add alice
```

Если этому же новому профилю нужен и выход в интернет через VPS, при создании используйте **вместо** предыдущей команды:

```console
python vcli-admin.py --host 198.51.100.42 --user donpedro --auth key --key id_lanfabric add alice --internet
```

LanFabric создаст ключи и выделит внутренний IP-адрес. Не запускайте обе команды подряд с одним именем: профиль создаётся один раз. Для изменения существующего профиля есть `edit`.

### 4. Установите VPN-приложение на подключаемом компьютере

Если к VPN будет подключаться ваш Windows-компьютер администратора, выполните:

```console
python vcli-admin.py --host 198.51.100.42 --user donpedro --auth key --key id_lanfabric install-client
```

Программа узнает выбранный на сервере тип VPN и предложит установку соответствующего приложения через `winget`. Подтвердите установку, если приложение ещё не установлено. Эта команда действует на **текущем компьютере** и не устанавливает приложение на другие устройства.

Для другого участника установите подходящее приложение на его устройстве. Если там есть файлы LanFabric и Python, тип можно указать без доступа к серверу:

```console
python vcli-admin.py install-client --client-type awg
```

Для стандартного WireGuard замените `awg` на `wg`. Автоматическая установка реализована только на Windows. На Linux установите выбранное VPN-приложение по инструкции для своего дистрибутива: подсказка `install-client` в этой версии ориентирована на Windows. Самому участнику Python и LanFabric не нужны, если приложение установлено отдельно, а профиль передал администратор.

### 5. Получите профиль и включите соединение

На компьютере администратора скачайте профиль:

```console
python vcli-admin.py --host 198.51.100.42 --user donpedro --auth key --key id_lanfabric config alice
```

В текущей папке появится `alice.conf`; программа также покажет полный путь. Повторная команда перезаписывает этот локальный файл. Профиль содержит закрытый ключ: передавайте его только владельцу устройства и не публикуйте в переписке с открытым доступом, в отчётах или в GitHub.

Откройте AmneziaWG или WireGuard, выберите импорт туннеля из файла, укажите `alice.conf` и включите его. **Туннель** — это зашифрованное соединение с сервером. Команда `config` только получает настройки; сама соединение она не включает.

На Windows для профиля с интернетом `config` также проверяет маршрут к публичному адресу сервера и при необходимости вызывает системный запрос прав администратора. Маршрут нужен, чтобы компьютер мог добраться до VPN-сервера через обычное подключение. Если программа сообщила, что маршрут добавить не удалось, сначала исправьте это по её подсказке, затем включайте туннель.

Маршрут настраивается на компьютере, где выполнена команда, и не переносится вместе с `.conf`. Если профиль с интернетом передаётся на другой Windows-компьютер, до включения туннеля настройте маршрут **там**:

```console
python vcli-admin.py --host 198.51.100.42 endpoint-route add
```

Для этого вспомогательного действия нужны Python и `vcli-admin.py`, но SSH-ключ участнику передавать не нужно: команда меняет локальный маршрут и не управляет сервером. После смены Wi-Fi или основного шлюза маршрут следует проверить повторно.

### 6. Проверьте результат

На устройстве участника с включённым туннелем выполните:

```console
ping 10.8.0.1
```

Ответы от `10.8.0.1` означают, что доступен внутренний адрес сервера. В Linux `ping` продолжается до нажатия `Ctrl+C`.

Для профиля **с интернетом через VPS** дополнительно проверьте:

```console
ping 8.8.8.8
curl -4 https://ifconfig.me
```

Последняя команда обращается к внешнему сервису, который показывает ваш видимый IPv4-адрес. В Windows PowerShell при необходимости используйте `curl.exe -4 https://ifconfig.me`. Ожидается публичный адрес выхода вашего VPS. Для профиля без `--internet` внешний адрес обычно останется адресом вашего обычного подключения — это правильное поведение.

Отсутствие ответа на один `ping` само по себе не доказывает отказ VPN: ответ может блокироваться сетевым экраном. Сопоставьте его с состоянием туннеля и реальным доступом к нужному ресурсу.

## Добавление второго устройства и повседневная работа

Теперь можно подключить второй компьютер. Создайте отдельный профиль, например `bob`, получите его через `config bob` и импортируйте на втором устройстве. Для выхода через VPS добавьте `--internet` при создании. **Каждому устройству нужен свой профиль**: не используйте один и тот же `.conf` одновременно на двух компьютерах.

Узнать выданные адреса и разрешения можно так:

```console
python vcli-admin.py --host 198.51.100.42 --user donpedro --auth key --key id_lanfabric list
```

Когда оба участника подключены, попробуйте обратиться с одного компьютера к VPN-адресу другого. Например, в проводнике Windows путь `\\10.8.0.3\ОбщаяПапка` откроет папку, только если компьютер действительно получил адрес `10.8.0.3`, папка с таким именем открыта для общего доступа и у вас есть разрешение на доступ. LanFabric не создаёт папки и не меняет их права.

### Изменить доступ в интернет

Для уже созданного профиля:

```console
python vcli-admin.py --host 198.51.100.42 --user donpedro --auth key --key id_lanfabric edit alice --internet true
python vcli-admin.py --host 198.51.100.42 --user donpedro --auth key --key id_lanfabric sync
python vcli-admin.py --host 198.51.100.42 --user donpedro --auth key --key id_lanfabric config alice
```

Здесь три разных действия: `edit` сохраняет решение, `sync` применяет сетевые правила, `config` получает профиль с новым направлением трафика. Отключите старый туннель в приложении участника и замените его профиль новым файлом, затем подключитесь снова. Для Windows сначала убедитесь в наличии маршрута к серверу.

Чтобы оставить только частную сеть, выполните ту же последовательность с `--internet false`. Старый профиль тоже требуется заменить: иначе устройство продолжит направлять интернет-трафик в VPN, где сервер уже запрещает его выпускать.

### Остановить и снова запустить VPN

```console
python vcli-admin.py --host 198.51.100.42 --user donpedro --auth key --key id_lanfabric stop
python vcli-admin.py --host 198.51.100.42 --user donpedro --auth key --key id_lanfabric start
```

`stop` отключает VPN для всех участников, сохраняя данные и ключи. `start` восстанавливает работу по сохранённым данным. Выполняйте нужную команду по ситуации; для перезапуска есть `restart`.

AmneziaWG восстанавливается после загрузки, если разрешён автозапуск. Его состояние показывает `autostart status`; команды `autostart enable` и `autostart disable` меняют будущий автозапуск, сохраняя текущее соединение. Если после перезагрузки VPN не работает, проверьте `status` и `health`, устраните указанную причину и выполните `start`. Повторный `init` для этого не нужен.

### Закрыть доступ участнику

```console
python vcli-admin.py --host 198.51.100.42 --user donpedro --auth key --key id_lanfabric block bob
```

`block` помечает профиль заблокированным и отключает его от VPN, сохраняя запись. В этой версии отдельной команды разблокировки нет; `edit --internet true` блокировку не снимает.

Для полного удаления профиля:

```console
python vcli-admin.py --host 198.51.100.42 --user donpedro --auth key --key id_lanfabric delete bob bob
```

Второе `bob` подтверждает имя удаляемого профиля. Если впоследствии создать `bob` заново, он получит новые ключи: старый файл подключения больше не подойдёт, потребуется новый.

## Если что-то не работает

Сначала определите, на каком этапе возникла проблема. Повторная установка редко является первым нужным действием.

| Что наблюдается | Что проверить |
| --- | --- |
| Не запускается `vcli-admin.py` | Версию Python, текущую папку и наличие обоих файлов программы |
| Не удаётся управлять сервером | Обычный SSH-вход с тем же адресом, пользователем и ключом; права `sudo` |
| Программа сообщает о разных версиях | Раздел [обновления](#обновление-lanfabric); не копировать серверный файл вручную |
| `status` показывает `STOPPED` после перезагрузки | Выполнить `start`, затем `health` |
| Туннель включён, но `10.8.0.1` недоступен | Правильный профиль и приложение, UDP 51820 у провайдера, маршрут к серверу на Windows |
| Сервер доступен, а второй компьютер — нет | Включён ли его туннель, верен ли адрес из `list`, разрешает ли его брандмауэр нужное приложение или ответы на `ping` |
| Частная сеть работает, интернет через VPS — нет | Разрешение в `list`, выполнение `sync`, обновление профиля, внешний интерфейс `eth0` и вывод `health` |
| По IP-адресу доступ есть, по имени сайта — нет | Настройки DNS — службы преобразования имён в IP-адреса; в выдаваемом профиле указан `8.8.8.8` |

В VPN-приложении смотрите время последнего обмена ключами (`latest handshake`) и счётчики переданных и принятых данных (`transfer`). Просто включённый переключатель ещё не подтверждает связь с сервером.

Для проверки маршрута на Windows:

```console
python vcli-admin.py --host 198.51.100.42 endpoint-route status
python vcli-admin.py --host 198.51.100.42 endpoint-route add
```

Первая команда показывает состояние, вторая добавляет маршрут, если это требуется. При неработающем туннеле сначала отключите его в VPN-приложении, чтобы восстановить обычный доступ.

Для подробного вывода добавьте `--debug` **перед** действием. Если нужен ручной ввод пароля `sudo`, есть параметр `--tty`. При запросе помощи укажите команду, версию, текст ошибки и результаты `status`/`health`; перед отправкой проверьте журнал и удалите секреты. Сам `.conf` с закрытым ключом не прикладывайте.

## Обновление LanFabric

Клиентский и серверный модули должны иметь одинаковую версию. Узнать версию локального клиента можно командой `python vcli-admin.py --version`; версия серверного модуля также запрашивается при выполнении серверных команд.

Версия состоит из трёх чисел. Если изменилось только последнее, например `0.0.16` → `0.0.17`, получите новые **оба** Python-файла на компьютер администратора и выполните:

```console
python vcli-admin.py --host 198.51.100.42 --user donpedro --auth key --key id_lanfabric patch
```

Команда сама передаст серверный модуль. Обычные серверные команды при таком несовпадении блокируются до обновления; `patch` не выполняет полную первоначальную настройку.

Если отличаются первое или второе число, текущий механизм требует `init`. Это переинициализация с последствиями для действующей сети, поэтому сначала прочитайте указания к соответствующему обновлению. Не запускайте её автоматически вслед за сообщением о несовпадении версий.

## Доступ к серверу по паролю

Ключ из основного примера — не единственный способ входа. При `--auth password` LanFabric для серверных действий временно добавляет свой SSH-ключ и разрешения `sudo`, выполняет команду, затем удаляет временные записи. Пароль не сохраняется на диск и не передаётся аргументом процесса. Это всё равно изменение настроек доступа на сервере, хотя и временное.

Если программа сообщила, что очистка не удалась, используйте её рекомендацию:

```console
python vcli-admin.py --host 198.51.100.42 --user donpedro --auth password untrust --temp
```

Для регулярного управления можно явно предоставить этому компьютеру постоянный доступ:

```console
python vcli-admin.py --host 198.51.100.42 --user donpedro --auth password trust TRUST
```

`TRUST` — подтверждение операции. LanFabric создаёт или использует ключ `~/.ssh/lanfabric_ed25519` и добавляет на сервер свои записи доступа. `~` обозначает домашнюю папку вашего пользователя. После этого пример команды выглядит так:

```console
python vcli-admin.py --host 198.51.100.42 --user donpedro --auth key --key ~/.ssh/lanfabric_ed25519 status
```

Отозвать постоянный доступ текущего компьютера можно через `untrust` с теми же параметрами подключения. Для удаления всех записей LanFabric у выбранного SSH-пользователя предусмотрено `untrust --all-lanfabric REMOVE-ALL-LANFABRIC-KEYS`; это затронет и другие доверенные компьютеры. Команда удаляет записи с маркерами LanFabric, а не весь список SSH-ключей пользователя.

## Краткий справочник

Справка доступна без соединения с сервером:

```console
python vcli-admin.py --help
python vcli-admin.py add --help
python vcli-admin.py install-client --help
```

В таблице приведена **конечная часть** команды. Перед ней добавляйте `python vcli-admin.py` и свои параметры подключения, как в примерах выше.

| Действие | Назначение |
| --- | --- |
| `init` / `init --no-amnezia` | Первоначальная настройка AmneziaWG / WireGuard; выбрать один вариант |
| `status`, `health` | Общее состояние и подробная диагностика |
| `start`, `stop`, `restart` | Запуск, остановка и перезапуск VPN без полной инициализации |
| `autostart enable` / `disable` / `status` | Включение, отключение и проверка восстановления AmneziaWG после загрузки |
| `add alice` | Новый профиль для частной сети |
| `add alice --internet` | Новый профиль с выходом в интернет через VPS |
| `add alice --comment "Ноутбук"` | Новый профиль с пояснением |
| `list` | Имена, адреса, разрешения и состояние профилей |
| `edit alice --internet true` / `false` | Изменение разрешения выхода через VPS; затем `sync` и новый `config` |
| `edit alice --comment "Домашний компьютер"` | Изменение пояснения к профилю |
| `sync` | Применение участников и сетевых правил из базы данных |
| `config alice` | Получение файла `alice.conf` в текущую папку |
| `block alice` | Блокировка профиля с сохранением записи |
| `delete alice alice` | Удаление профиля с подтверждением имени |
| `patch` | Обновление серверного модуля при отличии последнего числа версии |
| `install-client` | Проверка или установка приложения на текущем компьютере |
| `endpoint-route add` / `status` / `delete` | Управление локальным Windows-маршрутом к публичному адресу сервера |
| `trust TRUST`, `untrust` | Предоставление и отзыв постоянного доступа для управления сервером |
| `untrust --temp` | Очистка временных записей доступа LanFabric |
| `remove REMOVE` | Удаление VPN-пакетов и остановка VPN с сохранением данных |
| `purge PURGE` | Полное удаление LanFabric и его данных с сервера |

`remove` сохраняет `/opt/vpn-admin` и `/etc/wireguard`; `purge` удаляет и эти каталоги, а также выполняет очистку пакетов. Это действия для вывода установки из эксплуатации, не способы обычной остановки. Сохранение каталогов при `remove` само по себе не является резервным копированием.

У `install-client` есть параметры `--check-only` (только проверить), `--manual` (показать инструкцию) и `--yes` (согласиться на установку без вопроса). При перенаправлении вывода установка требует `--yes`. Явный выбор `--client-type awg` или `--client-type wg` позволяет не обращаться к серверу.

Параметр `add --admin` пока лишь устанавливает отметку в базе и сразу разрешает интернет. Полноценного разграничения прав администратора VPN нет; SSH-доступ этим параметром не выдаётся. Отметка меняется через `edit alice --admin true` или `false`, а разрешение интернета — отдельным `--internet`.

## Технические сведения

Этот раздел нужен для сопровождения и диагностики; для обычного подключения достаточно шагов выше.

| Настройка | Значение |
| --- | --- |
| Частная IPv4-сеть | `10.8.0.0/24` |
| Адрес сервера внутри VPN | `10.8.0.1` |
| Адреса участников | `10.8.0.2`–`10.8.0.254` |
| Порт VPN | `51820/UDP` |
| Сетевой интерфейс VPN на сервере | `wg0` |
| Тип VPN, в сообщениях `backend` | `awg` — AmneziaWG; `wg` — WireGuard |

Оба Python-модуля используют только стандартную библиотеку. Учётные записи хранятся в SQLite — локальной базе данных. Передачу и фильтрацию пакетов на сервере настраивает `iptables`, системными службами управляет `systemd`. В режиме WireGuard используется служба `wg-quick@wg0`; в режиме AmneziaWG версии 0.0.17 отдельной службы автоматического запуска нет.

Основные данные сервера:

| Путь | Содержимое |
| --- | --- |
| `/opt/vpn-admin/vsrv-admin.py` | Серверный модуль |
| `/opt/vpn-admin/vpn.db` | Участники, ключи и разрешения |
| `/opt/vpn-admin/backend` | Сохранённый выбор `awg` или `wg` |
| `/opt/vpn-admin/awg_params` | Общие параметры AmneziaWG |
| `/opt/vpn-admin/configs/` | Сохранённые профили участников |
| `/etc/wireguard/` | Конфигурация и ключи сервера |
| `/etc/sudoers.d/vpn-admin` | Правила административного запуска LanFabric |
| `/etc/sysctl.d/99-vpn-forward.conf` | Настройка передачи IPv4-пакетов |

В клиентском профиле поле `Endpoint` содержит публичный адрес из `--host` и порт сервера. Поле `AllowedIPs` определяет, какие адреса направлять через VPN: `10.8.0.0/24` для частной сети либо `0.0.0.0/0` для всего IPv4-трафика. На Windows команда `config` заменяет последнее значение на `0.0.0.0/1, 128.0.0.0/1`. Эти два диапазона также охватывают весь IPv4, но не включают встроенную блокировку трафика вне туннеля. Отдельный маршрут к `Endpoint` всё равно необходим.

Для AmneziaWG сервер сохраняет параметры `Jc`, `Jmin`, `Jmax`, `S1`, `S2`, `H1`–`H4` и включает их в серверную и клиентскую конфигурацию. Переносить только стандартные поля WireGuard или произвольно менять эти значения в профиле не следует.

При `sync` активные участники заново добавляются в VPN, а правила доступа пересобираются из базы. Разрешения на выход в интернет должны стоять перед общим запрещающим правилом; `health` проверяет этот порядок. Внешний сетевой экран провайдера эти команды не настраивают.

У проекта пока нет графического интерфейса управления, программного интерфейса для внешних приложений, полноценной модели ролей и переноса широковещательного трафика локальной сети. Подключение к ресурсам на устройствах проверяется отдельно от состояния сервера.

Разработчикам и тем, кто хочет разобраться глубже: [документация проекта](docs/README.md), [обзор архитектуры и известных проблем](docs/reviews/LanFabric_project_inspection_2026-09-18.md), [план дальнейших работ](docs/work_plan_ru.md). Для запуска существующих локальных проверок используется `python tests_local/run_local_checks.py`.
